1. このアプリの考え方と、推奨の使い方

1.1 なぜ Excel でも市販タスクアプリでもないのか

総務の仕事は「タスク」だけでできていません。契約更新には交渉の経緯があり、工事には先輩の助言があり、督促には「何回目か」という文脈があります。Excel の管理表はセルに収まる情報しか持てず、市販のタスクアプリはタスクとメモが別画面に分かれます。結果、情報が散らばり、探す時間が増え、管理表そのものが更新されなくなる — これがこのアプリが解決しようとした出発点です。

このアプリの答えはシンプルです：すべてを 1 つの Markdown ファイルに、文章として書く。タスクも、締切も、作業予定も、経緯メモも、上司の一言も、同じ場所に。そしてアプリがその文章を読み取って、カレンダー・ガントチャート・カンバン・期限一覧という「別の眺め方」を自動で作ります。

- [>] 施工計画書のレビュー                          Calendar  週の時間割（今日どう動くか）
  - @schedule: 7/7 13:00-15:00   ──読み取り──▶   Gantt     工程と期限の俯瞰（間に合うか）
  - @due: 7/10                                     Kanban    状態の分布（何が詰まってるか）
  - 養生範囲に通路が入ってない。要指摘              Agenda    期限超過・今日・今週（朝いち）

  カレンダー上で予定を動かすと、                     Tray      日時未定タスクの在庫
  Markdown の @schedule が書き換わる（双方向）       AST       構造確認（普段は使わない）

1.2 3 つの約束（このアプリの設計思想）

  • ① あなたの文章が唯一の正。アプリは専用データベースを持ちません。ビューで行った操作（ドラッグ・チェック）はすべて Markdown 本文への書き換えとして反映され、エディタでいつでも確認・修正できます。アプリを捨てても文章は残ります。
  • ② 管理のための作業をさせない。色を塗る・罫線を引く・ステータス列を選ぶ、といった「管理の管理」は不要です。文章に [>] や @due: と書けば、見た目はビューが勝手に整えます。
  • ③ 抜け漏れは機械に見張らせる。日付のないタスク、期限切れ、7 日放置、記法ミス — 人間が気合いで見張るのではなく、Health パネルと Agenda が検知します。あなたの仕事は「検知されたものに対処する」ことだけです。

1.3 推奨の使い方 — 4 拍子のループ

このアプリの使い方は、突き詰めると次の 4 拍子の繰り返しです。この後の全セクションは、この 4 拍子を総務の各場面に当てはめたものです。

拍子やること使う場所
① 書く依頼・思いつき・経緯を、考えずにまず文章にする。整理はあとエディタ（インボックス）
② 割り付ける「いつまでに（@due）」と「いつやるか（@schedule）」を決めるエディタ＋カレンダー
③ 眺める目的に合うビューで見る。朝は Agenda、計画は Calendar、工程は Gantt各ビュー
④ 検知に応える期限超過・放置・記入漏れの警告に対処する（週次で棚卸）Agenda・Health
いちばん大事な習慣を 1 つだけ挙げるなら：「締切（@due）を書いたら、やる時間（@schedule）も必ず確保する」。締切だけのタスクは"願望"です。時間を割り付けた瞬間に"予定"になります。カレンダーに置けない量のタスクを抱えていることに気づけるのも、この習慣の効能です。

1.4 最初のセットアップ（着任初日にやること）

  1. Obsidian で総務用フォルダ（Vault）を開き、総務メイン.md を 1 つ作る。最初はファイル 1 枚で十分。
  2. 冒頭に引用ブロック（>）で「連絡先・自分ルール」を書く（サンプルの冒頭を丸写しして書き換えるのが早い）。
  3. セクション（##）を業務の柱で切る：インボックス／契約管理／工事／イベント／備品／派遣／事業計画／後輩フォロー／年間イベント俯瞰。
  4. まず「年間イベント俯瞰」から書く（去年のカレンダーや前任者の記録から拾う）。未来の自分への貯金として一番利回りが良い。
  5. あとは日々の依頼を 4 拍子で回すだけ。ファイルが 500 行を超えて重く感じたら案件ごとに分割（設定が vault スコープなら分割しても全ビューに自動集約される）。

2. Markdown の書き方（詳細リファレンス）

2.1 タスクとステータス — 5 つの記号で仕事の状態を表す

## 【契約管理】委託・共通契約          ← ## 見出し＝案件の区切り

- 清掃委託契約 更新（8/31満了）        ← チェックの無い行＝タスクを束ねる「グループ」
  - [x] 現行契約の確認（単価・解約条項）      ← done：完了
  - [>] 変更覚書のドラフト作成               ← doing：いま自分が着手中
  - [!] 新単価の見積書待ち → ボール：松田さん ← blocked：相手ボール（待ち）
  - [ ] 法務レビュー依頼                     ← todo：未着手（自分ボール）
  - [-] 旧契約書の廃棄（更新完了後でよい）    ← hold：保留・いまは動かさない

覚え方：「x 終わった / > 進んでる / ! 止まってる（人待ち） / 空欄 これから / - 寝かせてる」。特に [!]（blocked）は総務の生命線です — 「私は待っているだけで、ボールは相手にある」を明示できるので、督促漏れと「自分がやってない感」の両方から解放されます。

2.2 時間のメタ情報 — @due と @schedule は別物

- [>] 施工計画書のレビュー（安全計画・養生範囲）
  - @schedule: 2026-07-07T13:00/2026-07-07T15:00   ← 「7/7 の 13〜15 時にやる」＝作業の時間ブロック
  - @due: 2026-07-10                                ← 「7/10 までに終わらせる」＝締切
  - @priority: 1                                    ← 優先度（1 が最高。付けるのは 1 と 2 だけで十分）
  - 養生範囲にサーバーラック前の通路が含まれていない。村井さんへ指摘予定   ← 経緯メモ

@due（期限）と @schedule（実施予定）を分けて書くのがこのアプリの核心です。上の例は「10 日締切だが、7 日の午後に片付ける」という意思まで表現しています。カレンダーには @schedule が時間ブロックとして載り、Agenda には @due が期限として載ります。

日付は省略記法が使えます（保存時もそのまま。アプリが解釈します）：

- @schedule: 26-07-07T13:00/15:00      → 2026-07-07T13:00 〜 同日 15:00 と解釈（年2桁・終了側の日付省略）
- @schedule: 2026-07-22/24             → 7/22〜7/24 の日単位（終日）レンジ。工事の工期などに
- @schedule: 2026-07-07T13/15          → 分を省略すると :00 扱い

間違えるとどうなるか：形式が不正な行（例：終了時刻の書き忘れ、区切りに「〜」を使う）はビューから静かに消えます。ただしエディタが波線で警告し、直せるものはワンクリック修正（クイックフィックス）が出ます。波線を放置しないこと — Health パネルの「記法ミス」検知にも同じものが出ます。

2.3 その他のメタ情報 — 文脈つきの実例で

▼ タグ：横串の検索軸。「ボール待ち」「突発」「派遣」など、セクションを跨いで集めたい語を付ける
- [!] 第2会議室モニターの修理見積 → ボール：購買・鈴木さん
  - @due: 2026-07-09
  - @tags: ボール待ち, 備品

▼ 依存：先行タスクが終わらないと始められない関係。ガントで意識でき、順番の間違いを防ぐ
- [ ] ケータリング発注（人数確定後3営業日以内）
  - @dependsOn: 参加人数の取りまとめ（各部幹事へ依頼済み・7/10〆）
  - @due: 2026-07-15

▼ 繰り返し：RRULE 形式。本文は 1 行のまま、カレンダー・ガント上で毎回展開される
- [ ] 備品棚卸（毎月第1金曜）
  - @schedule: 2026-07-03T14:00/2026-07-03T16:00   ← 起点。この曜日・時刻パターンで繰り返す
  - @repeat: FREQ=MONTHLY;BYDAY=1FR                ← 毎月第1金曜。FREQ=YEARLY なら毎年
  - @tags: 定例

2.4 メモ・引用 — このアプリの「文章力」を使い切る

- [!] 新単価の見積書待ち → ボール：松田さん（7/3督促済み）
  - @due: 2026-07-10
  - @tags: ボール待ち, 契約
  - 7/1 依頼。「本社から回答する」とのこと                ← ただの行＝経緯メモ。日付を頭に付ける習慣を
  - 7/3 電話督促。「週明けには」。次は本社窓口へ直接      ← 督促履歴とエスカレーション判断も残す
  > 先輩・田島さん「更新契約こそ解約条項を読め。         ← 引用（>）＝もらったアドバイスの定位置
  > 自動更新の通知期限を落とすと1年縛られる」

経緯メモと引用はタスクの子として保持され、ビューからタスクをクリックすればエディタの該当行へ飛べます。つまり「一覧で気づく → 1 クリックで経緯に戻る」が常に成立します。会議のメモを別ノートに書いてしまうと、この導線が切れます — そのタスクに関する情報は、そのタスクの下へ。

アンチパターン何が起きるか正しい形

- [ ] 資料作成

4. 仕事スタイル別レシピ 6 選

レシピ① 突発依頼（数時間後締切）が来たら

「15時までにお願いします」メールを Markdown で受け止める

  1. ファイル先頭の「今日のインボックス」セクションに 1 行で書く（考えない。書くだけ）。
  2. @due: に今日、@schedule: に今から作業する時間ブロック、@priority: 1、@tags: 突発。
  3. カレンダー（週表示）を開き、押し出された既存ブロックをドラッグで夕方や明日へ退避。玉突きを見える化する。
  4. 作業中の確認事項・判断はタスク直下にメモ（「会議室Cの扱い→戸田さん確認→除外でOK」）。
  5. 片付いたら [x]。後日、経緯ごと該当案件セクションへ移す。

レシピ② 年間イベントを忘れない・早めに動く

防災訓練・健康診断・大掃除・点検立会い…の「気づいたら直前」を根絶する

  1. 「年間イベント俯瞰」セクションに本番タスクを置き、@repeat: FREQ=YEARLY を付ける。毎年カレンダー・ガントに自動で現れる。
  2. 本番と別に「準備開始」タスクを 1〜2 ヶ月前の日付で置く。9/1 防災訓練なら「7/14 開催日確定・消防署連絡（@due: 7/31）」。
  3. 月に 1 回、ガントをズームアウトして年間俯瞰（毎月第 1 金曜の棚卸とセット）。

レシピ③ タスクスイッチが多くても「どこまでやったか」を失わない

10 案件並行・割り込み多数でも、戻ってきた瞬間に再開できる

  1. 着手したら [>]。doing は常に 1〜2 個まで。
  2. 中断する瞬間に、タスク直下へ 1 行：- 7/3 16:50 ここまで：5契約中3契約分ドラフト済み。残りは富士ゼロ系2件。時刻＋ここまで＋次やること。書くのに 20 秒、思い出すのに 20 分、の交換。
  3. 先輩・上司の助言はその場で引用（>）でタスク直下に。
  4. 再開はビューからタスクをクリック → 該当行へジャンプ → 直下のメモを読む → 続きから。

レシピ④ ボールの持ち合い管理（いま待ちなのは私か相手か）

「見積待ち」「回答待ち」の督促漏れをなくす

  1. 相手にボールが渡った瞬間 [!] にし、タスク名末尾に「→ ボール：松田さん（7/3督促済み）」、@tags: ボール待ち。
  2. 回答期限を @due に切る。「待ち」にも期限。期限が来たら督促、が機械的に回る。
  3. 毎朝、保存クエリ（status: blocked）を見る。督促したら日付つきで経緯に追記（エスカレーション判断も：「2 回目なので次は本社窓口へ」）。
  4. ボールが返ってきたら [ ] か [>] へ戻す。Health の stale 検知（7 日更新なし）が保険。

レシピ⑤ 後輩の心配なタスクを軽くウォッチする

マイクロマネジメントせず、詰まりと期限だけ見る

  1. 「後輩フォロー」セクション（または後輩ごとのファイル）に本人の案件をサブタスク粒度で置く。
  2. 見るのは期限（@due）と「手が止まっていないか」だけ。作業指示は書かず、観察と次の一手を書く（「手が止まっている様子。金曜に最初の一歩を一緒に決める」）。
  3. 週 1 回、本人と一緒にセクションを開いてチェック。相談と自分の回答も直下に残す（言った言わない防止＋本人の記録）。

レシピ⑥ 多案件並行のファイル構成

「どこに書いたか分からない」を構造で防ぐ

  • 最初は 1 ファイル（インボックス → 案件セクション群 → 後輩 → 年間俯瞰 → 保存クエリ）。セクション＝案件が基本単位。
  • 500 行を超えて重く感じたら分割：総務メイン.md／年間イベント.md／工事-5F空調.md。indexScope が vault なら分割後も全ビューに自動集約される。
  • 冒頭の引用ブロックに連絡先と自分ルール（未来の自分への申し送り）。

5. 1 日の回し方 — 場面別ウォークスルー

ここからは「新しく総務に来たあなた」への引き継ぎのつもりで書きます。総務の 1 日は予定どおりに進みません — だからこそ、崩れたときに立て直せる型を持っておくことが、この仕事を楽にします。

SCENE 1 ── 月曜 8:50「今日と今週を 15 分で組み立てる」

朝イチのルーティン

出社してメールを開く前に、まず Agenda を開いてください。メールから始めると他人の優先順位で 1 日が始まります。Agenda から始めると自分の約束から始まります。

  1. 「期限超過」から見る。ここにあるものは今日の最優先です。対処は 3 択 — ①今日やる（@schedule を今日に置く）、②期限を正直に延ばして関係者に一報（@due を書き換え、経緯メモに「7/6 ○○さんへ延期連絡済み」）、③実は完了していた（[x] にする）。期限超過を「見なかったこと」にだけはしない。
  2. 保存クエリ「ボール待ち一覧」（status: blocked）を開く。@due が来ているものに督促。督促したら必ず日付つきで経緯メモに残す — 上司に「あれ催促した？」と聞かれて 3 秒で答えられるのはこの記録のおかげです。
  3. カレンダー（週表示）で今日のブロックを現実チェック。月曜は会議で潰れがちです。ブロックが会議と重なっていたらドラッグで移す。今日 15 時以降に「予備の空き」を 1 枠残すのがコツ — 総務の午後には必ず何かが起きます。
先輩の声：この 15 分をサボった週は、水曜あたりで必ず「あれ忘れてた」が出ます。逆にこの 15 分さえやれば、あとは 1 日崩れても金曜に立て直せます。

突発依頼の 10 分

6. 検索・フィルタ（task-query）

各ビュー上部のフィルタバー（⛃ フィルタ → ステータス／タグ／テキスト／優先度／期日まで・から の入力欄が開く）で即席の絞り込みができます。よく使う条件は Markdown 内にコードブロックとして埋め込むと「保存された検索」になり、ノートを開くたびに結果が表示されます。

```task-query
status: blocked            # ボール待ち一覧（毎朝見る）
```

```task-query
status: todo,doing,blocked
due: <=2026-07-10          # 今週締切（未完のみ）
tag: 契約                   # タグ絞り込み（行を重ねると AND）
scope: vault               # vault（全体）/ folder / current（このファイルだけ）
```

使えるキー：status／tag／due:（<= または >= 日付）／priority:（<= 数値）／text:（本文部分一致）／scope。不正な行は無視されるだけなので、気軽に書いて試してください。

7. まだ実装されていない機能・概念（開発向け詳細）

ここから先は新人向けではありません。オーナーと開発チームのための「実装すべきだが未実装」の全体像です。凡例：Issue起票済み 仕様確定済み・未実装 構想段階

7.1 時間メタ 3 層モデル（Phase 004 の中核）仕様確定済み

2026-07-03 に確定した、本アプリの時間表現の完成形。現在の @schedule / @due の 2 メタに @plan を加えた 3 層＋仮置き修飾子で、「枠を切る → 時間を割り付ける → 期限を守る」の全段階を表現する。詳細仕様は project/plan/time-meta-spec-and-implementation-plan-2026-07-03.html、実装 Issue は issue-phase004-001〜005＋各ライブラリ Issue（計 23 件、起票済み）。

  • @plan — 「この期間の中でやらねばならない」バッファ込みの枠（WBS 的概念）。Gantt では schedule バーを包む点線枠。日付のみは終日解釈。祖先タスクから内部継承（親案件に @plan を書けば子タスクの検証に効く。Markdown へ自動追記はしない）。
  • 仮置き ? — @schedule?: のようにキー末尾に付けると「仮」。全ビューで半透明＋?バッジ。総務的には「会議室を仮押さえした状態」の表現。確定操作（? を外す UI）と、仮のまま直前に迫ったら警告する Health ルール（tentative-near）までがワンセット。
  • @due の期間対応 — 「受入期間の締め」等を 2026-07-10/07-15 で表現。Gantt はマイルストン◆（期間は ◆〜◆ 塗り）、Calendar は太線＋左端 ◄ の「ここまで」描画。
  • バリデーション — plan.start ≤ schedule ≤ plan.end ≤ due(end) 違反をエラー提示（入力は禁止しない）。「工事の検収予定が契約期限を超えている」類の矛盾を機械が拾う。
  • 残論点 R-1 — 「schedule」という名前が意味（意思表示・時間ブロック）に合っているか再考中。候補: @do / @work / @slot / @focus。Spec 起票（issue-phase004-001）までに要決定。

7.2 ビュー描画の拡張（Phase 004・ライブラリ側）Issue起票済み

  • 週末・祝日の色分け（gantt/calendar 共通）— 祝日はプラグインフォルダの JSON を設定で参照。「あと何営業日か」の誤認を防ぐ。issue-gantt-phase004-006 / issue-calendar-phase004-004
  • カレンダーの種別描き分け — タスク（左ボーダー）／予定（枠線ゴースト）／打合せ（塗り）。判定は「チェックなし＋@schedule＝予定」「タグ 打合せ/meeting＝打合せ」。issue-calendar-phase004-001
  • Gantt サブタスク展開＋期間なし行の DnD 予定化 — 親バーの下に子を行表示し、日時未定の子をタイムラインへドラッグすると @schedule が書かれる。時間ブロッキングの中核操作。issue-gantt-phase004-007/008
  • Gantt バー横ラベル・done/仮置きの描き分け・左パネルスリム化 — issue-gantt-phase004-001/004/005
  • Kanban breadcrumb — グルーピング解除時もカードに「セクション › 親カード › ユニット」を表示。issue-kanban-phase004-002
  • Kanban サブカードグループ DnD 表示位置バグ — 書き戻しは成功するが表示が動かない既知バグ。E2E で機械的再現済み（skip テストが再現手順）。issue-kanban-phase004-001（＝issue-phase000-003）最優先

7.3 入力体験（Phase 003 の未消化分）Issue起票済み

  • リマインド通知（issue-phase002-005）— 期限・開始時刻が来ても現状何も起きない。この仕事スタイルで最も痛い欠落（突発・督促・時限のすべてに効く）。@due の時刻対応（現状は日付単位で「15 時締切」を構造化できない）も同時に解決したい。
  • クイック追加モーダル／キャプチャ→インボックス→リファイル（issue-phase003-004/006）— ホットキー 1 発で 1 行追加。レシピ①の摩擦を根本から下げる。
  • メタ補完・期間デートピッカー（issue-phase003-008）— @s→@schedule 展開、カレンダーポップオーバーで開始・終了をクリック入力。日付の手打ちミスが消える。
  • チェックボックスのクリックサイクル・アクションピル（issue-phase003-007）、選択→ビューへドラッグでメタ付与（issue-phase002-004）、保存スマートリスト＋バッジ（issue-phase002-007）、グループ進捗ロールアップ（3/5・60%）（issue-phase003-002）、依存矢印と安定 ID（issue-phase003-003）、編集可能テーブルビュー（issue-phase003-005）

7.4 構想段階（Issue 未起票。完成度レポート・本ガイド作成時の提案）構想

  • 完了日・状態変更の自動記録（@done 等）→ 週報ドラフト生成 — チェックを付けた日付が残らないため「今週何をやったか」を機械が答えられない。org-mode の LOGBOOK / Obsidian Tasks の ✅ に相当する記録層と、done/doing/overdue を期間集計して Markdown で吐く報告生成。遡って付けられないデータなので早いほど資産になる。タスク直下に経緯を持つ本アプリは報告文生成で競合優位（完成度レポート §7.1-7.2）。
  • @ball（ボール保持者）メタ — 現在は「→ ボール：松田さん」という手書き規約＋タグ。構造化すれば「松田さん待ちの全件」「相手ボールの滞留日数」が引ける。blocked への状態変更時に「誰待ちか」を促す UI（org の WAITING 記録と同発想）とセットが理想。
  • @leadTime／年間俯瞰ビュー — 「本番の N 週間前に準備開始」を宣言すると準備タスクの期日が自動導出される仕組みと、12 ヶ月を一望する軽い年ビュー。現状はレシピ②の手動運用で回避。
  • 外部カレンダー（ics）読み取り — 会議予定が見えないと「空き時間にタスクを置く」計画の精度が上がらない。読み取り専用レイヤーとして calendar/gantt に重畳（書き戻しはしない）。打合せの種別描き分け（7.2）とも合流する。
  • 表示上の記法圧縮 — @schedule: をエディタ表示上だけアイコン化（データは正規形のまま）。Obsidian の Live Preview 的アプローチ。
  • doing 切替時のタイムスタンプ自動挿入 — レシピ③の「ここまでメモ」の行頭（日時）を自動で用意する軽量クロッキング。interstitial journaling の機能化。
優先順位の提案（オーナーの仕事スタイル基準）：①通知＋@due 時刻（毎日痛い）→ ②Kanban DnD バグ（信頼回復）→ ③完了記録→週報（上司報告の負荷）→ ④Phase004 時間メタ 3 層（計画力の底上げ）→ ⑤クイックキャプチャ → その他。
