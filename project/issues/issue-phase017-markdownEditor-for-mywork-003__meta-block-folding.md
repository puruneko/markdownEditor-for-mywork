# エディタでタスクのメタ情報ブロックを折りたためるようにする

## 背景
- リポジトリ: `markdownEditor-for-mywork`。
- 要望原文（「折りたfみ」は「折りたたみ」の誤字と読む）:
  > メタ情報の折りたたみ機能
  > 　@rv: 実装されていない。
- これまで「意味が未確定」として issue 化を保留していた（issue-phase016-markdownEditor-002 に記載）。
- 採用した解釈: Markdown エディタ上で、タスク行の下にあるメタ行（`- @key: value` / `- @key` とその子孫行）のまとまりを、タスク行を残したまま折りたためるようにする。
  - 理由1: 本リポジトリでメタ情報を直接目にするのはエディタ上であり、既にメタ行は専用装飾（`metatag-decoration.ts`）でブロックとして扱われている。
  - 理由2: Obsidian 標準のリスト折りたたみはタスクの子全体（サブタスクを含む）を畳むため、メタだけを畳む機能は存在しない。この欠けている機能が @rv の「実装されていない」に当たると判断した。

## 目的
タスクのメタ情報ブロックだけを折りたたんで1行の目印にでき、サブタスクや本文は表示されたままにできる。

## 現状
- `src/editor/` に折りたたみの実装は無い。
- `src/editor/metatag-decoration.ts` 31行 `META_LINE_RE = /^(\s*- )@([\p{L}\p{N}_]+)(\?)?(?::(.*))?$/u`。メタ行と、そのインデントより深い子孫行を「メタブロック」として装飾している。
- エディタ拡張は `src/plugin.ts` 196-200行付近の `registerEditorExtension` で登録。コマンドは 119-160行付近の `addCommand` で登録。

## 実装内容
1. 新規 `src/editor/meta-fold.ts`
   - メタブロックの範囲検出（純粋関数）: タスク行の直下から続く、タスク行より1段深いメタ行と、その子孫行の連続範囲。メタ行でない兄弟行（サブタスク等）が現れたら範囲終了。範囲検出は `META_LINE_RE` と同じ判定を使う（共通化してよい）。
   - 折りたたみ状態を CM6 の `StateField`（折りたたんだタスク行の位置の集合。ドキュメント変更で位置をマップ）で持つ。
   - 折りたたみ中は、メタブロック範囲（最初のメタ行の行頭〜最後の行末）を `Decoration.replace({ block: true })` 相当で1行のウィジェット「▸ メタ情報 (N件)」に置き換える（N = メタ行数。子孫行は数えない）。ウィジェットをクリックすると展開する。
   - 展開中は、メタブロック先頭行の行頭に小さなトグル「▾」を表示し、クリックで折りたたむ（Live Preview・Source Mode の両方）。
2. コマンドを追加（`src/plugin.ts`）
   - 「カーソル位置のタスクのメタ情報を折りたたむ/展開」
   - 「すべてのメタ情報を折りたたむ」「すべてのメタ情報を展開」
3. 既定は展開。折りたたみ状態は保存しない（ファイルを開き直すと展開に戻る）。
4. 折りたたみ範囲内にカーソルが入る編集（検索ジャンプ等）が起きた場合は、そのブロックを自動で展開する。
5. Markdown 本文は一切変更しない。

変更ファイル: `src/editor/meta-fold.ts`（新規）, `src/plugin.ts`, `styles/` 配下に折りたたみ表示用 CSS（新規ファイルを追加する場合は `esbuild.config.mjs` の結合リストにも追加）, テスト

## 完了条件
- メタ行を持つタスクで、トグルまたはコマンドによりメタブロックが「▸ メタ情報 (N件)」の1行になり、サブタスク行は表示されたまま。
- ウィジェットのクリック・コマンドで展開できる。
- 「すべて折りたたむ/展開」がファイル内の全タスクに効く。
- 折りたたみ・展開で Markdown 本文が変わらない（undo 履歴に残らない）。
- メタ行の装飾・日付ピッカー・Obsidian 標準のリスト折りたたみが従来どおり動く。

## テスト
- 単体: メタブロック範囲検出（メタのみ／メタ＋サブタスク／メタの子孫行あり／裸の `@key`／メタなし／ネストしたサブタスクのメタ）。
- 単体: StateField が文書変更で位置を正しくマップする。
- 手動: Obsidian で Live Preview / Source Mode の両方を確認。
