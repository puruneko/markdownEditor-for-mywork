## 1. このフェーズでの gantt のゴール

現状の gantt は「schedule バーを描いて動かせる」だけ。Phase 004 完了時には**時間メタ 3 層モデルの可視化装置**になる:

- 1 つのタスク行に **plan（点線枠）・schedule（バー）・due（◆）** が同時に描け、仮置き（半透明+?）と完了（グレー+✓）が見分けられる。
- バー横に任意ラベル（ステータス等）、ヘッダに週末・祝日色。
- サブタスクを展開でき、**期間なしサブタスクをタイムラインへドラッグして予定化**できる（onSchedule コールバック）。

gantt はメタ名（@plan 等）や祝日の意味を**知らない**。すべて prop（`plan` / `milestone` / `tentative` / `status` / `trailingLabels` / `holidays` / `weekend`）で受ける。prop 型の正は本体の issue-phase004-004。

## 3. gantt 固有の実装規約（全 Issue 共通）

1. **座標変換関数は 1 つ**: 日時→x 座標の変換は既存のバー描画と同じ関数を必ず使う。独自計算を書くと、ズーム・スクロール時にその要素だけズレる（002/003/005 すべてに効く）。
2. **SVG の重なりは描画順**: 背面から「列背景（006）→ plan 枠（003）→ バー → ◆（002）→ ラベル（005）」の順で描く。z-index は SVG では効かない。
3. **表示範囲計算への算入**: 新しい時間要素（milestone・plan）を追加したら、タイムラインの最小/最大日付計算に必ず含める。含め漏れると「データはあるのに画面外で見えない」事故になる（002/003 の要点に個別記載あり）。
4. **色は CSS 変数**: 新しい色は必ず CSS 変数（`--gantt-*`）にしてホスト上書き可能にする。ハードコード禁止。
5. **状態は持たない・コールバックで返す**: リサイズ幅（001）・折り畳み（007）・予定化（008）は内部 `$state`＋コールバック通知まで。永続化・書き戻しはホストの責務。ライブラリが自分でノードデータを書き換えることは**禁止**（データはホストから一方向。書き戻し→再パース→再描画のループが本体の設計）。
6. **luxon は単一インスタンス前提**: DateTime はホストから受けたものをそのまま使う。`instanceof` 判定が false になったら本体 esbuild の resolve 問題（obs-0009）を疑う。
7. **検証はライブラリ単体＋本体実機の二段**: lib 内テスト（リポジトリの test 構成を最初に確認）に加え、**本体側で `npm run test:obs:e2e` を必ず回す**。本体ビルドは lib の src を直接コンパイルするため、lib の変更は本体ビルドに即反映される（事前ビルド不要）。E2E の書き方・shadow DOM の注意は本体 `project/knowledge/obsidian-plugin-testing.md`。
