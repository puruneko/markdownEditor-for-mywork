# markdownEditor: 開発者モードでのElementsタブ選択解除問題は調査済み・原因は必須機能によるものと判明（追加のコード変更は非推奨）

対象リポジトリ: markdownEditor-for-mywork

## 1. Title
markdownEditor: 開発者モードでDOM要素の選択が解除される問題について、既に完了している調査結果（原因＝日付メタ情報のチップ⇔生テキスト切り替えによるDOM再生成、必須機能と判断）をユーザーに提示し、対応要否の最終確認を得てクローズする

## 2. Background
入力要望(ユーザー原文):
「開発者モードでエレメントをクリックすると、obsidianのHTML全体もしくはbodyに近い階層のどこかが更新され、Elementsタブもデフォルト表示に戻りでクリックした要素をたどれない。この拡張機能を切ると解消されるため、この拡張機能にこのような機能が必須かどうか確認する。必須でない場合は開発者モードでエレメントを辿れるようにロジックを修正して。」

本要望は過去にも同様の内容で提起されており、コード調査の結果、**原因の特定と必須性の判断は既に完了している**ことを確認した。以下は今回の調査で再確認した内容である。

- 静的コード調査（`grep`等）では、DOM全体・`document.body`・Obsidianのアプリコンテナ相当の階層を書き換えるようなコードは本プラグイン内に見つからなかった。
- 実機（Obsidian、Electron/Chromium）上で`MutationObserver`を用いた計測を行った結果、クリックやカーソル移動によるDOM変更は`.cm-content`（エディタ本体）配下に厳密に局所化されており、`document.body`やアプリのコンテナ階層への波及は確認されなかった。
- 原因は、`src/editor/metatag-decoration.ts`の`metatagValuePlugin`（271行目付近で定義）にある。この機能は、`@due`/`@schedule`/`@plan`などの日付系メタ情報の行について、カーソルがその行に重なっていないときは読みやすい「チップ」表示（`Decoration.replace`によるwidget）にし、カーソルがその行に重なると生テキストの色付け表示（`Decoration.mark`）に切り替える、という実装になっている（日付を人間可読なチップ表示とテキスト編集の両方に対応するための、本プラグインの中核機能）。
- Chrome DevToolsのElementsパネルは、**現在選択中のDOMノードそのものが破棄・再生成されると、たとえその変更がごく局所的であっても、選択状態を失いデフォルト表示に戻る**という仕様を持つ。ユーザーがDevToolsで日付チップの`<span>`を選択した状態のまま、キーボード操作等でカーソルがその行に出入りすると、上記のwidget⇔mark切り替えによってそのDOMノードが破棄・再生成され、選択が解除される。これが「HTML全体が更新されたように見える」体験の実体であり、実際のDOM変更範囲はごく限定的である。
- このwidget⇔mark切り替えは、日付メタ情報をチップ表示（読みやすさ）とテキスト編集（生の値の直接編集）の両方に対応させるための中核機能であり、これを削除・簡略化すると日付のテキスト編集ができなくなる。**必須機能と判断される。**
- 緩和策の検討: CodeMirror 6の`Decoration.replace`(widget)と`Decoration.mark`は本質的に異なる種類の装飾であり、両者を切り替える際にDOM要素の同一性を保つ手段はCodeMirrorのAPIレベルで提供されていない。チップ表示を維持したまま編集可能にする（例: 常にwidgetのまま内部に`<input>`を持たせる等）といった代替実装は、日付ピッカーの起動方式・確定操作を含むメタ情報編集システム全体の再設計に相当し、保守的な修正の範囲を超える。
